# Алгоритм синхронизации векторов BTIman-BTIwork

## 🎯 ПРАВИЛЬНАЯ АРХИТЕКТУРА СИНХРОНИЗАЦИИ

### 📤 BTIman (координатор заданий):

#### 1. Подготовка векторов:
1. **Читает** `c:\mega\DBM\vectors_bti.json` (исходный файл)
2. **Переименовывает** файл в `vectors_bti_work.json`
3. **Записывает метаданные** файла в БД через API:
   - `lFileSize` - размер файла в байтах
   - `tmFileTime` - время создания/модификации файла
   - Количество векторов в файле

#### 2. Создание заданий:
1. **Создаёт задания** для векторов 0-(N-1) где N = количество векторов
2. **Записывает задания** в БД через API
3. **Запускает мониторинг** выполнения

### 📥 BTIwork (воркер заданий):

#### 1. Проверка заданий (каждые 5 секунд):
```csharp
while (true)
{
    // 1. Проверяем наличие новых заданий в БД
    TaskStats stats = await GetTaskStats();

    if (stats.iNew > 0)
    {
        // 2. Получаем метаданные файла векторов из БД
        var metadata = await GetVectorFileMetadata();

        // 3. Проверяем наличие файла с нужными параметрами
        if (CheckVectorFile(metadata.lFileSize, metadata.tmFileTime))
        {
            // 4. Файл готов - загружаем векторы и работаем
            LoadVectors();
            ProcessTasks();
        }
        else
        {
            // 5. Файл не готов - ждём дальше
            LogMessage("⏳ Ожидание синхронизации файла векторов...");
            await Task.Delay(5000);
            continue;
        }
    }

    await Task.Delay(5000);
}
```

#### 2. Валидация файла векторов:
```csharp
private bool CheckVectorFile(long expectedSize, DateTime expectedTime)
{
    string filePath = @"c:\mega\DBM\vectors_bti_work.json";

    if (!File.Exists(filePath))
        return false;

    var fileInfo = new FileInfo(filePath);

    // Проверяем размер и время модификации
    return fileInfo.Length == expectedSize &&
           Math.Abs((fileInfo.LastWriteTime - expectedTime).TotalSeconds) < 10;
}
```

## 🔄 ПОСЛЕДОВАТЕЛЬНОСТЬ РАБОТЫ

### Сценарий 1: Первый запуск
1. **BTIman** переименовывает `vectors_bti.json` → `vectors_bti_work.json`
2. **BTIman** записывает метаданные в БД
3. **BTIman** создаёт задания в БД
4. **BTIwork** обнаруживает новые задания
5. **BTIwork** получает метаданные файла из БД
6. **BTIwork** проверяет - файл готов ✅
7. **BTIwork** загружает векторы и начинает работу

### Сценарий 2: Файл ещё не скопирован на удалённую машину
1. **BTIwork** обнаруживает новые задания
2. **BTIwork** получает метаданные файла из БД
3. **BTIwork** проверяет - файла нет ❌
4. **BTIwork** ждёт 5 секунд и повторяет проверку
5. **Пользователь** копирует файл на удалённую машину
6. **BTIwork** обнаруживает готовый файл ✅
7. **BTIwork** загружает векторы и начинает работу

### Сценарий 3: Файл устаревший
1. **BTIwork** обнаруживает новые задания
2. **BTIwork** получает метаданные файла из БД
3. **BTIwork** проверяет - размер/время не совпадают ❌
4. **BTIwork** сообщает о необходимости обновления файла
5. **Пользователь** обновляет файл
6. **BTIwork** начинает работу

## ✅ ПРЕИМУЩЕСТВА АРХИТЕКТУРЫ

1. **Автоматическая синхронизация** - воркеры ждут готовности файла
2. **Валидация целостности** - проверка размера и времени
3. **Отказоустойчивость** - система работает при любой последовательности запуска
4. **Ясная диагностика** - понятные сообщения о состоянии синхронизации
5. **Масштабируемость** - легко добавлять новые воркеры

## 🛠️ ТЕХНИЧЕСКИЕ ДЕТАЛИ

### API Endpoints:
- `POST /api/tasks/vectors/metadata` - запись метаданных файла
- `GET /api/tasks/vectors/metadata` - получение метаданных файла

### Таблица БД:
```sql
CREATE TABLE VectorMetadata (
    Id SERIAL PRIMARY KEY,
    lFileSize BIGINT NOT NULL,
    tmFileTime TIMESTAMP NOT NULL,
    iVectorCount INTEGER NOT NULL,
    tmCreated TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
