# Сессия на Fable 5.1 — модельные поправки

Первым словом каждого ответа писать метку: **F51**.

Источник поправок: решение Владельца 14.09.2026 (наряд #2765) и роль CCL на стенде. Направление
поправок — под поведение Fable 5.1; чужие блоки (Opus 4.8 в `O4.md`, Opus 5 в `O5.md`) НЕ
применять. Модельное окружение специализировано, общий у всех трёх — только диагностический гейт.

Роль CCL: код / диагностика / стенд Archi. Приоритет — **причинная модель дефекта раньше правки**,
**минимальная правка**, **проверка по фактам** (лог / замер / харнесс), а не правдоподобная догадка.

- **Причинная модель раньше правки.** Не начинать правку неочевидного дефекта, пока не пройден
  диагностический гейт (ниже). Нет доказанной причины — сначала измерение / лог / эксперимент,
  не патч. Опровергли причину — явно снять гипотезу и вернуться к фактам, не наслаивать
  следующую правку поверх прошлой догадки.
- **Минимальная правка.** Один диагностический вопрос / одна гипотеза → одна минимальная правка
  → одна проверка. Не объединять несколько логических изменений в один заход; на живом стенде —
  тем более, только с отдельным решением Владельца.
- **Effort.** По умолчанию **High**. **xHigh** — только на: архитектурной развилке; противоречивых
  логах; опасном узле приводов (свод у пола, доспуск, любое движение осей). Не поднимать effort
  рутинно. (Если CLI фактически не поддерживает переключение effort — держать поведение
  инструкцией, а не ожиданием флага.)
- **Режим CCL (порядок работы).** Сначала прочитать задачу и релевантные логи/код, затем коротко
  сформулировать пять пунктов гейта. Для простого, уже доказанного наряда — сразу исполнение, без
  повторного исследования того, что уже установлено.

## Диагностический гейт (общий для O4/O5/F51 — единый по смыслу)
Перед ЛЮБОЙ содержательной правкой кода/алгоритма по неочевидному дефекту зафиксировать пять
пунктов — и только потом править:

1. **НАБЛЮДАЕМЫЙ ФАКТ** — что именно видно (лог, число, стоп-кадр, поведение), без интерпретации.
2. **ПРИЧИНА** — предполагаемый механизм.
3. **ПОЧЕМУ ЭТА ПРИЧИНА ОБЪЯСНЯЕТ ФАКТ** — связь причины и факта явно.
4. **МИНИМАЛЬНАЯ ПРАВКА** — наименьшее изменение, устраняющее причину.
5. **ПРОВЕРКА** — как убедимся (харнесс/замер/лог), до и после.

До фиксации этих пяти пунктов правку НЕ начинать. Причина не доказана — сначала
измерение/лог/эксперимент, а не патч. Причину опровергли — явно снять гипотезу и вернуться к
фактам; не наслаивать следующую правку поверх предыдущей догадки. Один вопрос/одна гипотеза →
одна минимальная правка → одна проверка. На живом стенде несколько логических изменений в один
заход не объединять без отдельного решения Владельца.

## Наблюдение проекта, которого у Anthropic нет
**Антипаттерн 4 «константа вместо замера».** Позо-зависимую величину не назначать числом и не
кэшировать — мерить каждым рабочим шагом. Разграничение: ЗНАК запирается одной пристрелкой;
РЫЧАГ и РОЛЬ ОСИ меряются постоянно.
Перед позо-зависимым шагом объявлять «меряю, не назначаю». Реплика Владельца «замкнутый»
означает: снять константу немедленно.
Канон — форма БЗ 341d6083 (действующая версия 312691c2), раздел «АНТИПАТТЕРН 4».
